# Xxlang: 解释运行 vs 编译执行 性能对比报告

| 项目 | 配置 |
|------|------|
| **CPU** | Intel(R) Xeon(R) Platinum 8180 CPU @ 2.50GHz |
| **OS** | Linux |
| **Go** | go1.26.1 linux/amd64 |
| **测试日期** | 2026-03-14 |

---

## 测试方式

### A. 解释运行 (源代码)
```bash
./xxl run fib_naive.xxl
```
流程: 源代码 → 词法分析 → 语法分析 → 编译 → 执行

### B. 字节码运行 (预编译)
```bash
./xxl compile --bytecode fib_naive.xxl  # 预编译
./xxl run fib_naive.xxb                  # 运行
```
流程: 字节码 → 反序列化 → 执行 (跳过解析和编译)

### C. 独立可执行文件
```bash
# 将字节码嵌入 Go 程序编译为独立可执行文件
go build -o fib_standalone main.go
./fib_standalone
```
流程: 独立程序 → 加载字节码 → 执行

## 详细分析

### 执行时间分解

```
┌─────────────────────────────────────────────────────────────┐
│ 解释运行 (源代码)                                           │
├─────────────────────────────────────────────────────────────┤
│ 词法分析  │ 语法分析 │ 编译  │ ════════ 执行 ════════════  │
│   ~1ms   │   ~2ms  │ ~2ms │       ~6,280 ms               │
│    <0.1%  │  <0.1%  │ <0.1%│         99.9%                 │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 字节码运行                                                  │
├─────────────────────────────────────────────────────────────┤
│ 反序列化 │ ═══════════════════ 执行 ══════════════════════  │
│   ~1ms  │              ~6,440 ms                          │
│  <0.1%  │                99.9%                             │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ 独立可执行文件                                              │
├─────────────────────────────────────────────────────────────┤
│ 加载 │ ═══════════════════ 执行 ══════════════════════════  │
│ <1ms │              ~6,240 ms                             │
│ <0.1%│                99.9%                               │
└─────────────────────────────────────────────────────────────┘
```

### 性能差异原因

| 因素 | 影响 |
|------|------|
| 解析/编译开销 | ~5ms (占总时间 <0.1%) |
| 反序列化开销 | ~1ms (比解析编译更快) |
| 执行时间 | ~6,240ms (占总时间 99.9%) |

## 结论

### 对于计算密集型任务 (如 fib(35))

| 结论 | 说明 |
|------|------|
| **编译收益可忽略** | 解析+编译 ~5ms vs 执行 ~6,240ms |
| **字节码无性能优势** | 反序列化开销抵消了省去的编译时间 |
| **独立可执行文件无运行优势** | 执行逻辑完全相同 |

### 对于频繁启动的小脚本

| 结论 | 说明 |
|------|------|
| **字节码略有优势** | 跳过解析编译，启动更快 |
| **独立可执行文件部署方便** | 单文件分发，无需源码 |

### 建议使用场景

| 场景 | 推荐方式 |
|------|----------|
| 开发调试 | 源代码解释运行 |
| 生产部署 (频繁执行) | 字节码 或 源代码均可 |
| 生产部署 (分发) | 独立可执行文件 |
| 计算密集型 | 使用 Go/Python 等原生语言 |

## 补充说明

### Xxlang 的定位

Xxlang 是一个**嵌入式脚本语言**，设计目标不是计算性能，而是：

- ✅ 快速启动
- ✅ 易于嵌入 Go 应用
- ✅ 简洁语法
- ✅ 安全的内存模型
- ✅ 尾调用优化支持

### 性能优化方向

如需提升计算性能，可考虑：

| 优化方向 | 预期收益 | 复杂度 |
|----------|----------|--------|
| JIT 编译 | 5-10x | 高 |
| 寄存器式虚拟机 | 20-40% | 高 |
| 函数内联 | 10-30% | 中 |
| 调用 Go 函数 | 即时 | 低 |
